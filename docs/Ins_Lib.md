## 0 Ins_Lib 搭建

新建灵感库目录，准备一组长期关注的 RSS 信息源 放进工作目录。然后发送：

```markdown
帮我在当前工作目录构建一个「个人灵感库」。
参考 Karpathy 的 LLM Wiki 方法论：
https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f
我会提供一批 RSS 订阅源，之后每天都会有新的文章和信息进入这里。
这个知识库的目标不是做一个 RSS 收藏夹，而是让 Agent 随着信息不断进入，持续形成一个会自己整理、关联和更新的灵感 Wiki，帮助我发现值得关注的主题、观点、趋势、产品、案例，以及未来值得创作的内容方向。
RSS 获取到的原始内容作为 Raw Sources，尽量完整保留来源、标题、发布时间、原文链接等信息。在此基础上，由 Agent 持续维护整理后的知识库：识别不同信息之间的关联，把同一主题的新旧信息连接起来，更新已有认知，而不是每天产生一堆彼此孤立的摘要。
重点关注「这条信息为什么值得留下」以及「它和过去的信息有什么关系」。区分单纯新闻、持续趋势、重要观点、有价值案例和真正值得进一步创作的灵感，避免把所有内容都当成同等重要。
随着资料积累，这个库应该越来越能够回答：最近什么值得关注、某个主题发生了什么变化、有哪些反复出现的信号、哪些信息可以组合成新的选题，以及我过去围绕某个方向积累过哪些素材。
整个系统保持简单、透明、可维护，以本地文件、Markdown 和 Agent 为核心，不要引入不必要的数据库、向量库或复杂基础设施。
请根据这些目标自行规划合适的目录和 Wiki 结构，并为后续每日 RSS 自动入库设计清晰、简单的维护规则。
```

灵感库创建成功以后，设置定时任务，提示词：

```markdown
读取个人灵感库中配置的 RSS 订阅源，获取自上次执行以来的新内容，并按照当前知识库的维护规则完成入库。
保留新内容的原始信息和来源，然后理解其中真正有价值的信息，并更新现有的主题、趋势、观点、案例和灵感等 Wiki 内容。
重点寻找新信息与已有知识之间的关系：能更新已有页面就优先更新，不要为每篇 RSS 文章都创建孤立的知识页面；发现新的重要主题时再创建新页面。
注意去重，避免重复处理已经入库的文章。所有重要判断和总结都应能够追溯到原始来源。
不要只是生成一份“今日 RSS 摘要”，目标是让整个个人灵感库随着每天的新信息持续生长和更新。
```

## 3 工作流

### 3.1 公众号Workflow

```
raw/inbox/*.md           1837 条待加工的裸新闻 ← 每天 rss_ingest.py 往这里倒
   │  ① 入库（Agent 通读 → 判分类/留存价值 → 先搜后建）
   ▼
wiki/sources/<slug>.md   判断页（值不值得留、和旧信息什么关系）
   │  同一个信号反复出现 → 累加
   ▼
wiki/signals / topics    趋势页 / 实体页  ← 灵感的说服力来源
   │  跨条合成、人工或 Agent 撰写（这一步不是自动的）
   ▼
wiki/inspirations/       想法池：选题草图 + 可用素材 + 内容草图
   │  工作台 ③ 点「拿这条去写」→ 登记 status=writing
   ▼
tools/wxpub/out/<slug>/  00_brief → 02_final → images/ → 04_preview → copy_ready
   │  ④ 生成 ⑤ 存草稿
   ▼
公众号草稿箱              → 发表后再回流成 knowledge 卡（wiki/知识卡/）
```

## 4 公众号 / 今日头条 / 小红书 / 视频流水线工作台

公众号的工作台：

目前还缺少复盘模块。

**视频工作台的核心模块如下：**

### 4.1 **今日工作台**

展示用户当前最需要处理的任务：

• 待确认的 AI 选题

• 待完善的文案

• 待拍摄的视频脚本

• 待发布内容

• 待录入数据的视频

• 待复盘内容

• 最近新增灵感

### 4.2 **IP 定位中心**

保存用户的个人 IP 档案，包括：

• IP 名称

• 所属赛道

• 目标受众

• 用户痛点

• 价值主张

• 人设关键词

• 内容支柱

• 表达风格

• 禁止使用的表达

• 变现方向

• 当前阶段目标

IP 定位需要支持历史版本，不要直接覆盖旧版本。

### 4.3 **爆款拆解库**

用户可以录入：

• 来源平台

• 视频链接

• 作者

• 视频标题

• 封面标题

• 口播文案

• 发布时间

• 播放和互动数据

• 用户备注

AI 自动分析：

• 目标受众

• 用户痛点

• 选题角度

• 核心冲突

• 封面承诺

• 开头 5 秒

• 情绪设计

• 内容结构

• 金句

• 传播原因

• 可以复用的模式

• 是否适合当前用户的 IP

• 可以衍生出的新灵感

### 4.4 **灵感库**

灵感可以来自：

• 用户手动输入

• 爆款拆解

• AI 复盘

• 评论区反馈

• 用户上传的资料

• AI 根据历史内容自动生成

每条灵感需要保存：

• 灵感内容

• 来源

• 标签

• 创建时间

• 成熟度

• 适合的平台

• 关联的爆款、复盘或历史内容

• 当前状态

### 4.5 **选题库**

AI 根据灵感生成多个候选选题，每个选题必须包含：

• 视频标题

• 封面标题

• 开头 5 秒内容

• 核心观点

• 目标受众

• 用户痛点

• 情绪方向

• 内容结构建议

• 与 IP 的匹配度

• 与历史内容的相似度

• AI 推荐理由

用户可以：

• 采用

• 修改

• 淘汰

• 换一个角度

• 继续扩展

• 填写淘汰原因

用户的选择和修改必须保存，不能只保存最终选题。

### 4.6 **口播文案**

根据用户确认的选题生成口播文案。

建议分两步：

* 先生成内容结构和观点顺序。
* 用户确认后生成完整文案。

需要支持：

• 多个文案版本

• 用户直接编辑

• AI 局部改写

• 缩短或扩写

• 调整开头

• 调整语气

• 提取金句

• 查看 AI 原稿和用户终稿的差异

• 标记是否符合用户本人语气

#### 4.6.1 **视频脚本**

根据选题和口播文案生成视频执行方案，包括：

• 时间段

• 口播内容

• 画面内容

• 景别

• 人物动作

• 字幕重点

• 素材建议

• 音效或转场建议

• 预计时长

第一版只做脚本方案，不做视频剪辑和自动发布。

#### 4.6.2 **发布与数据中心**

用户手动登记发布记录：

• 发布平台

• 视频链接

• 发布时间

• 使用的文案版本

• 使用的脚本版本

支持在不同时间录入数据快照：

• 播放量

• 5 秒留存

• 完播率

• 点赞

• 评论

• 收藏

• 转发

• 主页访问

• 新增关注

数据不能只保存最新值，需要保存不同时间点的变化。

#### 4.6.3 **AI 复盘中心**

AI 复盘需要结合：

• IP 定位

• 原始灵感

• 选题

• 最终文案

• 视频脚本

• 发布数据

• 用户主观感受

• 评论区反馈

• 相似历史内容

• 爆款拆解结论

复盘输出：

• 哪些判断被数据验证

• 哪些判断出现偏差

• 开头、结构、表达和 IP 匹配的问题

• 值得继续使用的内容模式

• 应该停止做什么

• 应该继续做什么

• 下次测试建议

• 可以生成的新灵感

• 可以直接进入选题库的新选题

#### 4.6.4 **全局搜索**

可以搜索：

• IP 定位

• 爆款案例

• 灵感

• 选题

• 文案

• 视频脚本

• 发布记录

• 复盘结论

支持按照类型、标签、平台、状态和时间筛选。

### 4.7 **内容状态流转**

每条内容都需要有清晰状态：

灵感

→ 待生成选题

→ 选题待确认

→ 文案创作中

→ 脚本准备中

→ 待拍摄

→ 待发布

→ 已发布

→ 待复盘

→ 已复盘

用户需要能够从一条灵感追溯到最终视频和复盘，也能够从一条复盘查看它后来生成了哪些新灵感。

### 4.8 **验收标准**

第一版完成后，必须能够跑通以下完整流程：

1. 用户建立 IP 定位。
2. 用户录入一个爆款案例并完成 AI 拆解。
3. 用户输入一条灵感。
4. AI 结合 IP 定位和爆款拆解生成多个选题。
5. 每个选题包含视频标题、封面标题和开头 5 秒。
6. 用户采用、修改或淘汰选题，系统保存判断。
7. AI 根据确认后的选题生成口播文案。
8. 用户修改文案，系统同时保存 AI 原稿和用户终稿。
9. AI 生成视频脚本方案。
10. 用户登记视频发布信息和真实数据。
11. AI 结合完整上下文生成复盘。
12. AI 根据复盘生成新灵感。
13. 用户可以追溯整条内容链路。
14. 关闭并重新打开 App 后，数据仍然完整。
15. 用户可以搜索、备份、恢复和导出自己的内容。
